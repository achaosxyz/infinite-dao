# 轻量个人法宝实施方案

## 1. 状态与范围

- 本方案对应的个人法宝已实现并完成离线与原生验收；现行能力和规则以 `docs/design/` 与实际代码为准，验收结果以验证报告和 Owner 复核为准。
- 实施使用隔离测试和验证产物，不修改私密配置或玩家存档；仅在用户明确授权时执行提交。
- “发包”暂按“法宝”的笔误理解；任务发布、悬赏与委托系统不在范围内，如需该含义须另行确认。
- 实施沿用 Core、Application、Infrastructure、Game、Agents 的现有职责，不新增工程、依赖或通用装备框架。
- “完整修仙世界观”在本方案中指器物来历、修为门槛、认主御使、宗门传承、战后归属与失落重现彼此自洽，不指一次性实现丹、器、符、阵和飞升等全套系统。

## 2. 目标与非目标

目标是让玩家记住“谁得到了什么、为何失去、后来传给了谁”，同时保留宗门自动经营的定位。

本期必须包含：

1. 镇宗法宝保留，继续按现有规则影响全宗。
2. 每名在世人物最多携带一件个人法宝，效果只作用于持有者。
3. 日常获取、携带、同类升阶和传承自动进行；玩家只围绕重点培养人物选择是否赐予。
4. 法宝在寿尽、历练、战争、流亡和灭宗后有明确去向。
5. 获取、赐予、回收、传承、遗失、重获和缴获可沿史书追溯。
6. 离线模式完整可用，不依赖模型产生名称、效果或归属结果。
7. 规则与叙事一致：低境弟子不能直接御使高阶遗宝，战中缴获不能用于本场交锋，散修和敌宗也遵循同样的器物规则。

明确不做：多装备栏、自由词条、品质养成、强化、洗练、耐久、套装、炼器生产链、交易市场、器灵对话、手动刷宝副本，以及把镇宗法宝改造成个人法宝。不增加夺舍、血契反噬、法宝渡劫或独立法力条；本期不把“本命法宝”写成已实现能力。

### 2.1 休闲体验硬约束

- 法宝相关的必需操作为零：忽略所有赐予入口，也能自然获得、使用、自动换上同类更高阶器物和完成传承；没有法宝不阻止培养、历练、开战或终局。
- 默认交给执事，只对重点人物开放“赐予”；曾受赐的人物详情保留“交给执事”以撤销人工干预，不要求重新设为重点。不增加全员配装页、清库存任务、祭炼倒计时或领取战利品按钮。
- 自动换新只发生在同类且严格更高阶时，不为了战斗与历练来回切换类型；手动赐予保留玩家选择，不被自动立即换走。
- 法宝获得、升级、遗失和传承不新增待决议事、不暂停过月。普通门人的变动并入月报；重点人物也只作非阻塞提示，不制造确认弹窗或未读待办压力。
- 器阶和最低境界保留修仙含义，但规则由系统执行；玩家主要看“谁持有什么、效果是什么、经历是什么”，不需要学习后台字段和概率公式。

## 4. 玩法规则

### 4.0 修仙世界观约定

以下是本项目的设定边界，不宣称是所有修仙作品共有的规则，也不把未实现的世界背景当作可操作系统。

| 世界观层面 | 本期约定 | 可验证的落点 |
|---|---|---|
| 天地与器物 | 灵矿、灵材和灵脉构成器物的物质与灵气背景，器物须有具体来历 | 发现记录包含实际历练地域与来源事件；不凭空写出额外矿山或秘境地图 |
| 修士与修为 | 沿用炼气、筑基、金丹、元婴、化神、返虚六境，器物不能替代自身修为 | 模板规定最低御使境界；战斗仍遵守既有境界差规则 |
| 法器、灵器、法宝 | 作为个人器物的三个固定称谓，分别对应炼气、筑基、金丹起用；金丹以上不另开装备升级境界线 | 称谓由模板推导，不设置刷取品质、升级经验或突破材料 |
| 镇宗与随身 | 区分的是使用范围，不是把镇宗法宝理解为个人法宝的下一品阶 | 两类不互转，镇宗仍作用全宗，随身只作用本人 |
| 祭炼与认主 | 以自身灵识御使器物，允许主动交出和死后重新认主 | 在合法领取的安全节点自动完成，不设置额外等待月份、按钮或材料费用 |
| 师承与道统 | 法宝可以跨人物、跨代甚至跨宗延续，但不是人物死后自动生成一件纪念品 | 同一 ID 保留来源、历任持有人和实际流转事件 |
| 散修与敌宗 | 人物脱离宗门不等于失去全部个人物品，战胜对手也不等于洗劫所有幸存者 | 生还散修保留随身物；缴获只处理死亡者和真正夺得的库存 |
| 因果与机缘 | 机缘是受既有历练、地域和归属约束的规则结果，不是文字许愿 | 失物留在实际地域，后人只能通过真实的历练或战事重获 |

宗门风格通过少量固定模板表现，不新增五行相克、功法适配度或宗门专属装备限制。拟采用的命名与形制示例：

| 宗门风格来源 | 器物示例 | 规则类别 |
|---|---|---|
| 青云剑宗 | 听雨剑 | 御敌 |
| 赤霞宗 | 赤霞火印 | 御敌 |
| 百草谷 | 青木护符 | 护身 |
| 天工门 | 百炼护镜 | 护身 |
| 镜水宗 | 澄心灵镜 | 护身 |
| 玄霜门 | 玄霜飞剑 | 御敌 |
| 雷霆阁 | 惊雷尺 | 御敌 |
| 金禅寺 | 金莲念珠 | 护身 |
| 星罗宫 | 星斗护盘 | 护身 |
| 幽篁楼 | 竹影短刃 | 御敌 |

- 示例名称是待实施的本地内容，不表示当前已经存在对应物品；不要求“十宗×三个器阶”铺满模板矩阵。
- “风格来源”不是获取地点或宗门绑定：青云门人可以使用缴获的赤霞火印，物品背景也不能伪造一位从未存在的炼器师。
- 同名器物可以有不同 ID 和经历；真正的辨识度来自发现者、发现地、前任与关键战事，不靠不断生成更夸张的名字。
- 旧物原主不明时明确写“原主不详”；只有真实持有、赐予或流转记录存在时，才使用“师门遗宝”“前任掌门遗物”等具体称呼。
- 飞剑、镜、印、珠、符等形制都占用同一个随身位置，不因外形扩展出武器栏、防具栏或消耗符箓系统。

### 4.1 法宝类型与效果

- 镇宗法宝：现有生成来源、数值与生效规则保持不变。
- 个人法宝只设御敌、护身两种互斥效果，来自固定模板，不随机拼装属性；器阶在生成时确定，永不升级。
- 首批提供30个固定模板，按“御敌／护身×炼气／筑基／金丹”六个规则组划分，每组五种名称、形制与图标。组内最低境界和效果完全相同，丰富的是内容，不增加词条、相克或套装规则；不要求铺成十宗专属装备矩阵。

| 个人器阶 | 最低御使境界 | 御敌类：本人伤害提高 | 护身类：本人最终历练遇险概率相对降低 |
|---|---|---|---|
| 法器 | 炼气 | 8% | 15% |
| 灵器 | 筑基 | 12% | 20% |
| 法宝 | 金丹 | 16% | 25% |

- 一件物品只有所在列类别的一项效果，不同时具有御敌与护身；元婴至返虚仍使用该上限，不追加可无限追逐的装备层级。
- 风险降低为乘法，例如20%相对降低表示原遇险概率乘以0.8，并非直接减20个百分点，不能保证生还。
- 上述分档与数值是初始平衡提案，须经测试与实际流程验证后确定，不宣称已平衡。
- 不修改境界伤害倍率、突破条件、寿元或现有护道规则；随行护道人的法宝不把个人效果分享给弟子。
- 个人效果仅在本人满足境界要求并实际持有时生效；领取时自动完成认主，库存和遗失物均无加成，不再增加“携带但等待生效”的中间状态。
- 宗门战力预估在对应人物的分量中反映当前生效的御敌加成，不能再给全宗乘一次；历练类不得虚增战力。

### 4.2 获取与遗失法宝重获

1. 新个人法宝只从成功历练归山时自动发现，玩家与敌宗使用同一规则；已有物品还可以通过赐予、传承、缴获和重获流转，不额外创建副本。
2. 先处理归山与已有物品分配，只有发现者仍有空位或同类升阶需求，且现有库存不能满足时，才尝试新发现。每宗本局第一次符合条件的新发现保底成功，后续暂按10%概率；每次归山最多一次，不重试刷取。手动保留当前器物的人物不触发替换型新发现。
3. 新法宝使用本人当前境界可御使的最高固定器阶：空手时选择类别并从对应组的五种固定模板中取一，已有物品时只选同类且严格更高阶组的模板，无合格候选则不创建物品、不抽额外随机数。新物有独立 ID、发现月份与来源事件，优先由发现者在归山安全节点领取。五种造型没有数值优劣，不随机拼装，不让玩家反复刷取同档更好数值。
4. 遗失法宝保留在原地域；成功历练者在该地域优先重获一件遗失物，按 ID 稳定选取，本次不再判定新生成。
5. 重获、缴获与回收不受新发现条件阻止；旧物先真实入库，再按自动分配规则使用，不销毁既有物品来维持库存数量。
6. 不开放刷宝按钮，不因暂停、浏览详情、切换培养对象或读取存档重掷结果。
7. 发现事件可用“古洞遗物”“旧阵残器”等本地叙事交代来历，但这些是该次历练的实际事件内容，不宣称已新增可进入的副本、炼器生产线或坊市交易界面。
8. 同一遗失物只允许一个归属；先按串行提交的实际结果处理重获，后续结果不能再次捡取。捡到尚不能御使的旧物时收入库存，不放宽境界要求。
9. 实际战役胜利并占领地域后，在本场死亡与缴获结算完成时，将该战场已有的遗失个人法宝按 ID 收入胜方库存；只取无持有人、无宗门归属且地域匹配的物品，不搜走同地域在世散修的随身物。不要求领取者达到御使境界，之后分配仍受境界与认主约束。
10. 守方保有地域不额外触发搜取；和平赎地、主动撤离、单纯地域易主或战役取消不算战场重获。此类地域中的失物仍可通过实际成功历练重获。

首次保底按本宗真实新发现的来源事件判定，复用 `OriginEvent` 和 `RelicChange`，不新增进度计数器。缴获、镇宗法宝、丢失旧物、模式切换和读取存档不重置保底；若已有库存足以满足需求则先使用旧物，不为兑现保底复制一件新宝。

不设库存三件门槛，也不要求玩家清库。旧物优先复用，只有本人确有补位或同类升阶需求时才尝试创造新物；没有合格接收者的既有遗宝可继续封存。物品与历史仍会随人物更替增长，须验证长期存档体积，不把“按需发现”冒充世界总量硬上限。

### 4.3 自动携带与玩家干预

- 默认自动填补空位，并在安全节点为托管人物换上同类、严格更高阶且可御使的库存物；这里“升阶”只指换另一件物品，不改变原物的 ID、模板或器阶。旧物回库并保留原历史，不跨类型反复配装，不为同档数值重掷。
- 自动分配只考虑满足模板最低境界的人物；无人能御使的高阶遗宝留库待传承，不能降阶、拆解或吞掉。
- 新发现的物品优先给发现者本人；其余库存按器阶降序、法宝 ID 升序处理，为每件物品选择最高优先级的合格接收者：先重点培养人物，再按境界、资质降序与人物 ID 升序排列。可接收指空手，或未手动保留且持有同类低阶物；不从其他活人手中自动抢物。
- 换下的旧物在同一个安全节点继续参与后续较低器阶的分配，使先前用不了高阶物的空手人物也能接到旧物；最多三个固定器阶依次处理，不引入通用队列或反复全员换装。人物突破或归山时也触发此检查，不让“已持同类低阶物”堵住高阶传承。
- 本人正在历练、护道或远征时，不允许赐予、交换或自动改装；不能给前线人物隔空换宝。
- 自动补位在完整事务结束后的安全节点执行，不在交锋、死亡结算或宗门归属变化中途运行。
- 玩家从重点培养人物详情发起赐予或调配，来源只能是本宗库存或本宗已归山的在世人物。
- 赐予的规则统一为“选中的法宝交给目标，目标旧物回库”；若来自另一名人物，其空位由执事在安全节点补齐。不要求把目标旧物强塞给原持有人，只校验新接收者的境界；任一参与人物在外则整体拒绝，失败不发生部分转移。
- 玩家赐予后默认保留此物，不被自动升阶换走；详情内点“交给执事”即可恢复默认托管。解除重点培养不没收物品，也不撤销既有赐予；原受赐者仍能从自己的详情恢复托管，无需重新设为重点。恢复托管只改变偏好，在外人物等归山后才可能换新；NPC 不增加偏好管理。
- 调配只改变真实归属、持有人及是否保留手动选择，不生成资源、重掷效果或重置发现月份。反复点击已持有的同一件物品不叠加加成、不追加物品流转。
- 认主并入安全节点的实际领取事务，一次完成；战利品仍须先结束本场交锋与死亡结算，再入库和分配，不能反向影响本场结果。回库或遗失即解除当前使用关系；同一持有人流亡或转散修不丢失个人效果。
- 认主不是不可转移的灵魂绑定；主动赐予视为交出旧印，死亡后旧印消散。日常温养只作为正常修行中的背景叙述，不产生额外供养扣费、隐藏损耗或累积属性。
- 首版不增设灵石费用、手动祭炼、祭炼倒计时、温养进度条与弹窗确认链；沿用提交版本、待决议事、局终等现有约束，实际流转记入史书。
- 普通人物由系统自动安排，不提供全员逐个配装入口；解除重点培养不会自动没收其法宝。
- 不提供单独卸下按钮，以免与自动补位互相抵消；“旧物回库”只作为库存赐予或死亡等实际流转的结果，不额外增加一套手动空槽管理。

### 4.4 死亡与宗门变动

| 场景 | 个人法宝去向 |
|---|---|
| 宗门人物在山门寿尽 | 回本宗库存，记录持有人与死亡事件，再由自动补位形成传承 |
| 人物在历练、护道或远征途中寿尽 | 遗失于实际历练地域或战役目标；同行者只能在随后成功归山或实际占领战场时按重获规则带回，不直接送入远方库存 |
| 历练完成时主角遇险陨落、护道人生还 | 法宝由护道人带回库存，不直接挤占其随身位置 |
| 历练无人带回，包括护道人同时殉身 | 死者的随身法宝遗失于历练地域，保留实体与原来源 |
| 战死且本方最终守住或夺得战场 | 回本宗库存 |
| 战死且对方宗门掌握战场 | 转入对方库存，后续自动分配；不得假设击杀者一定生还 |
| 战死且战场由无宗门守卫掌握 | 遗失于争夺地域 |
| 平局 | 遵循当前守方保有地域的规则决定战场归属，不新增战斗胜负定义 |
| 玩家失守进入流亡 | 幸存门徒保留随身物，库存与镇宗法宝沿现有薪火保留规则处理 |
| 人物在流亡或灭宗时变成散修 | 在世人物继续持有随身物，宗门归属随之清空，不复制、不凭空缴获 |
| 敌宗失守并被灭 | 镇宗法宝与未携带库存转入胜方；在世散修的随身物不被批量转移 |
| 无胜方的宗门自然解体 | 未携带个人库存遗失于解体前山门；镇宗法宝不擅改既有规则 |
| 无宗门人物寿尽 | 在正常月结的被动寿元处理中死亡，随身物遗失于最后可靠地域，不按无主地排序把物品瞬移到另一处 |

不新增指定继承人系统。首版“传承”指同一法宝回库后交给下一位真实人物，并串起前任记录。

- 地域来源优先使用实际历练地、战役目标，其次为人物所属山门；脱离宗门或自然解体前先记录可靠地域。散修没有独立移动系统时，不虚构其行踪。
- 当前月结只按存续宗门推进人物，这是必须补齐的生命周期缺口：本期为无宗门在世人物增加被动年龄、境龄与寿元结算，避免转成散修即停止衰老，使其遗物能回到地域循环。
- 被动散修结算只覆盖月初已为散修且仍在世的人物，每月年龄与境龄各增加一次，按现有寿元表判断死亡；本月由宗门转成散修者不得再计一次年龄。除此不增加散修修炼、突破、自由移动、招揽或追宝 AI，也不为死亡抽取额外随机数。
- 缴获表示持有权变化，不追认对方是合法师承；赠与、继承、战利品和失物重获使用不同史书措辞。
- 不新增自动复仇、失主追杀或寻宝任务。原宗后人只能通过现有战争与历练实际取得旧物，才生成“故物重归”的记述。

### 4.5 叙事与规则必须共同成立的故事链

以下是验收场景，不是预先写入每局世界的固定剧情，也不另建人物关系系统。

1. **少年得器、后人成名**：炼气弟子在实际历练中得到法器，经自动认主后随身使用；多年后寿尽，器物回库交给下一位真实人物，记录前任与后任，而不是再抽一件同名法宝冒充传承。
2. **高阶遗宝、暂待传人**：金丹修士留下法宝，现存门人境界不足时封存库存；后来托管人物达到金丹，即使已持同类低阶物也会自动换上遗宝，旧物回库再传。不为了讲故事强迫突破、跳过境龄或要求玩家先手动卸下旧物。
3. **护道归来、遗物归山**：历练弟子陨落，生还护道人带回其随身物；护道人也陨落时，旧物留在原地域，不能同时出现在宗门库存。
4. **战场易主、故物重归**：持有人战死，胜方缴获并交给敌宗人物；后来原宗通过真实战斗再次缴获同一 ID，史书才将其称为旧物重归，不凭空创建“追回”结果。
5. **山门破碎、道统未绝**：流亡幸存者带着已认主的器物重建，不因山门易主突然解除个人效果；转为散修者也保留自身物品，与宗门库存分开结算。

界面与叙事不得把最低御使境界写成器物可以帮助跨境必胜，不得把护身概率降低写成免死，也不得将未来可能加入的器灵、本命血契、飞升或法宝渡劫写成当前能力。

### 4.6 最小闭环与允许的停留状态

| 当前状态 | 真实触发 | 下一状态 |
|---|---|---|
| 尚未发现 | 成功历练、确有需求、无合格库存且命中一次发现判定 | 新物在安全节点由发现者实际携带，自动认主生效 |
| 库存／境界不足待传 | 合格人物补位、托管人物同类升阶，或玩家合法赐予 | 同一物品由实际人物持有并御使，不等待下一月 |
| 托管人物已持低阶物 | 进阶或归山等安全节点存在合格同类高阶库存 | 自动换新，旧物回库；不跨类循环换装 |
| 宗门人物携带 | 合法调配、在山寿尽或战后己方回收 | 回库或换人，按实际持有人重新认主 |
| 敌宗人物携带或敌宗库存 | 持有人战死且对方掌握战场，或敌宗库存被真正夺取 | 胜方库存，后续按相同规则分配 |
| 人物携带或无胜方宗门库存 | 在外寿尽、历练无人带回或宗门自然解体 | 同一地域遗失，保留同一 ID |
| 宗门人物携带 | 在世人物脱离宗门 | 散修持有，不重置认主，继续被动衰老 |
| 散修持有 | 正常月结达到寿元 | 最后可靠地域遗失，保留同一 ID |
| 地域遗失 | 该地域实际成功历练，或战役胜利占领后搜取 | 实际获取方库存，再按相同规则分配 |

境界不足、无人合格补位或升阶、玩家明确保留现物、地域暂不可达都是合法停留状态，不是必须用脚本强行推进的死锁；“已拿着同类低阶物”本身不再阻止自动传承。闭环要求每条已承诺的流转都有真实触发和唯一去向，不要求每件法宝必被捡回、每个宗门必得到高阶物品或玩家必定复仇成功。终局后世界停止推进，也不再强制完成散修寿尽或失物重获。

## 5. 数据与一致性

### 5.1 沿用 `Relic` 的最小扩展

拟增加以下字段，最终名称随实现核对，不新增单独模块：

| 字段 | 含义 |
|---|---|
| `Scope` | `sect` 或 `personal`，默认 `sect`，确保既有法宝不被重新解释 |
| `TemplateId` | 个人法宝的固定模板 ID；模板集中定义形制、来源风格、最低御使境界及唯一效果，不分散保存多套属性 |
| `HolderId` | 可空的人物 ID；只作为个人法宝的唯一持有关系，不在人物上重复保存法宝 ID |
| `RegionId` | 个人法宝最近一次可靠地域；遗失时就是失落地点，持有时不据此虚构独立移动 |
| `KeepAssigned` | 默认 `false`；玩家明确赐予或选择保留时为 `true`，仅用于避免自动换掉本次选择，不增加锁定等级或偏好列表 |
| `LastEventId` | 最近一次流转事件；与原有 `OriginEvent` 一起支持历史追溯 |

- `Owner` 对个人法宝表示当前所属宗门；散修持有或地域遗失时为空。
- `Power` 保持镇宗战力字段的含义，个人法宝为0；个人效果和境界要求统一读取模板，不在存档重复保存百分数，也不能解析 `Effect` 文字执行规则。
- 模板是 Core 中的少量固定数据，不新增配置 DSL、模板加载框架或运行时属性组合器；镇宗法宝保持现有自由名称与效果字段。
- 不另设可独立写入的装备状态字段，通过持有人、宗门和地域推导“库存封存／本人御使／地域遗失”三个状态；认主不再保存额外倒计时。
- 保留原始发现月份、来源事件和法宝 ID，转移不重建实体，不删除已死亡人物来截断因果。

### 5.2 史书中的最小结构化引用

仅有 `Causes` 和中文文字不足以可靠查询“某人曾持有什么”或区分同名物品。因此拟在 `Chronicle` 增加一个可空的 `RelicChange` 数据字段；原有非个人法宝事件保持空值。

- `RelicChange` 只包含本次事实的六个引用：`RelicId`、`FromHolderId`、`ToHolderId`、`FromOwner`、`ToOwner`、`RegionId`。人物 ID 可空，宗门可为空，地域必须真实有效。
- 每条个人法宝事件只记录一件物品；赐予涉及新物交付、旧物回库和来源人物后续补位时，各记真实流转，与持有关系在同一事务提交，不能只完成一半。仅改变托管选择时使用普通决策记录，不伪造持有转移。
- 引用保存事件发生时的前后值，不从人物当前宗门倒推过去，也不从中文标题、小传或 `Effect` 中解析 ID。
- 死亡人物页按前后持有人 ID 查询；物品经历按 `RelicId` 与 `Causes` 查询；“故物重归”仅在历史明确记载当前接收宗门曾实际拥有该物时使用。
- 初次发现事件保存真实发现地域；以后即使物品移动，回看其来历也不使用当前 `Relic.RegionId` 冒充发现地。
- 这只是既有史书中的业务引用，不增加第二套持有历史集合、通用事件框架或独立人物关系系统；旧事件不补造虚构引用。

### 5.3 必须成立的不变量

1. 法宝 ID 唯一，新增时使用世界 ID 分配；导入检查 `NextId` 不与法宝等既有实体冲突。
2. 同一人物最多持有一件个人法宝；持有人必须存在且在世，其 `SectId` 必须与法宝 `Owner` 一致，包括散修的空归属。
3. 无持有人的个人法宝只能位于有效存续宗门库存，或有效地域；库存与遗失不能同时成立。
4. 遗失时无持有人、无宗门归属且地域有效；镇宗法宝没有个人模板、持有人或个人地域，`KeepAssigned` 为 `false`。
5. 个人模板必须是明确允许的固定 ID，拒绝未知模板和通过额外字段注入自由属性；名称与背景文字不具规则权限。
6. 归属变化后不得给旧宗门、未参战人物、已死人物或不在场护道人提供效果。
7. 新个人法宝的来源与流转事件必须存在，且发现月份不晚于当前月份；来源事件不得形成前向引用或因果环。
8. 所有手动调配先完整校验，再一次提交；失败不改变原世界。
9. 持有人必须达到模板最低境界；`KeepAssigned` 只允许用于玩家本宗在世人物的当前随身物，且只能经玩家赐予或保留命令设为真。回库、遗失或转为散修时清除，取消重点培养不清除；不能因恢复托管而在人物仍在外时换装。
10. 个人法宝的可靠地域必须存在，丢失地点不得由无关排序生成；判断库存或遗失必须结合持有人与宗门，不能只看地域字段是否有值。
11. 个人法宝流转事件必须引用对应物品、真实人物与有效宗门；同一物品的前后关系须能沿流转链连续衔接。最后一条流转的持有人和宗门去向与当前状态一致，不允许跨物品拼接因果；事件地域是当时发生地，不能要求它随之后正常移动而改写。

### 5.4 结算时序与历史

- 战斗先使用开战时持有关系完成双方交锋与死亡，再生成战役事件，随后按最终战场控制权处理死者法宝，最后进入掌门继承、失守和灭宗处理。
- 历练先确定主角与护道人最终生死，再确定回收或遗失；不能在护道人是否殉身尚未确定时提前回收。
- 寿尽先取得人物当前活动地域并生成死亡事件，再按在山、在外或散修分支回库或遗失；删除失效历练、战役或清空宗门前必须完成定位，不能事后把山门当成所有死亡地点。
- 战场重获在实际胜利占领与本场死者去向确定后执行，且在掌门继承、失守与灭宗变动前完成；同一批法宝先按 ID 处理，避免刚遗失或已缴获的物品重复入库。
- 无宗门人物的被动年龄处理与宗门成员年龄处理互斥，以月初散修集合避免同月重复衰老；完成全部死亡、归属及活动清理后才执行自动分配。
- 历练重获先入库存；归山记录移出活跃历练后，在完整结算且下一批新活动选人之前执行补位。不能因发现者的旧历练引用尚未移除而拒绝其携带，也不能先发起新远征再给已在外人物隔空装备。
- 当前批历练先完成生死与活动清理，再按归山记录 ID 顺序处理“原地重获—已有库存分配—必要的新发现—领取与旧物继续分配”；整批处理完成才开始新活动。不能在第一次补位后就让人物出发，再补发新物或旧物。
- 自动分配在获得／回收、归山、人物进阶、新人加入和恢复托管等安全节点检查，只补空位或同类严格升阶；手动保留时不换，既无空位也无更高阶候选时不改写状态、不追加日志。不增加每月配装任务、资源消费或反复弹窗。
- 复用 `Chronicle.Causes`：流转事件引用上次流转与本次死亡、战役或历练事件，并更新 `LastEventId`。
- 初次发现以历练归山事件为因；原有镇宗法宝不强行补造历史事件。
- 认主与实际领取一次提交，后续从真实持有关系判断效果；不靠每月重写状态或制造“温养成功”日志。人工保留不影响属性，仅抑制同类自动升阶；归属改变的场景统一维护该标记。
- 人物出发、战役结算与宗门解体等真实位置变化处更新个人法宝的可靠地域；先记录最后山门，再清空宗门与人物归属。
- 所有写入走 Core 与 Application 现有复制、校验、串行提交、保存流程，模型不直接修改法宝。

## 6. 存档与兼容

- 拟将新世界版本升至3，同时支持六宗迁移世界和十宗世界，不给旧世界补建宗门。
- 版本1先沿用已存在的立绘校验与迁移规则升级至2；版本2按旧版规则校验后补齐法宝字段，再升级至3并执行新不变量校验。
- 旧法宝全部保持 `sect`，既有名称、战力、归属、发现月份和合法来源不变；无个人法宝是合法状态。
- 对合法旧档中空缺的新增字段只赋默认值；不能把非法新版数据当旧档静默修复。现有旧版允许的来源事件取值与新增严格规则应按版本分别处理。
- 声明为版本1或2的输入不得携带个人法宝非默认字段或非空 `RelicChange`；发现此类数据直接拒绝，不能先覆盖默认值或升级版本，把伪装成旧档的新版非法关系洗成合法状态。
- 版本3个人法宝必须具有合法模板、可靠地域与合法的托管标记；复制、读取和恢复不得重选模板、抹去前任或丢失玩家的保留选择，也不得因一次加载而偷偷重新配装。
- 旧史书的 `RelicChange` 默认空；版本3新产生的个人法宝事件必须保存结构化引用，并在复制、导入及恢复时校验，不从旧中文记录猜测补齐。
- 迁移不调用规则随机数、不生成法宝或新历史，不更改月份、人物、地图与后台计划。
- 首版不承诺旧客户端读取版本3；导入失败按既有流程保留当前世界，禁止批量重写玩家文件。
- 验证 `Copy()`、JSON 往返、自动与手动槽、导入导出都保留持有关系和历史链；不只测试反序列化成功。

## 7. 原生界面与 Agent 边界

- 人物列表只增加一行名称摘要；详情先显示“持有什么、效果、来历”，器阶、御使境界与历任持有人按需展开，区分背景风格和真实发现地点。
- 无物时写“暂无随身法宝，执事自动安排”，高阶物写“境界不足，留库待传”；不使用待办红点、祭炼倒计时或一整页配装参数催促操作。
- 重点培养人物详情提供可选的赐予入口，仅列出本宗归山且目标可御使的物品，标明原持有人与“目标旧物将回库”；在外、议事中或局终时明确说明不可操作原因，不弹多层确认。
- 选择当前已持物表示“保留此物”；受赐者无论是否仍为重点，都可点“交给执事”恢复自动换新，不增加单独锁定页。当前在外时提示“归山后自动安排”，只改变偏好，不隔空换宝。
- 已死亡人物详情按结构化引用显示其曾持法宝，区分“死亡时去向”和“如今下落”，不能把当前持有人误写成死者，也不能把后来的再次缴获说成当时即发生。
- 史书复用法宝事件与既有因果查看能力，展示“得宝—赐予—陨落—缴获／传承”，不新建独立历史系统。
- 战报保留当场使用的个人法宝名称、器阶与加成快照，避免后来转移或换新后回看战报失真；御敌与镇宗效果分别说明。
- 法宝图片只作识别辅助，按第7.1节控制在30张固定模板图标；不新增主导航、全员装备页、图鉴收集奖励或抽卡展示。当前只规划资源，不在本轮生成图片。
- Agent 只读观察按需补充法宝摘要，明确可用境界与效果上限；展示总战力只是参考，实际出征仍按可出战阵容评估，不把库存或在外人物的物品算成前线即战力，不开放新工具或法宝配装请求循环。
- 日常流转并入既有月报与史书；同月重点人物的多次变化可合并非阻塞提示，史书保留完整事实，不生成待处理议事或清库提示。

## 8. 实施顺序与文件范围

### 阶段一：数据、兼容与规则入口

- 在 `GameState.cs` 扩展 `Relic` 与史书的可空 `RelicChange`，战报仅增加必要的当场个人法宝快照字段。
- 在 `GameEngine.cs`、`WorldFactory.cs`、`GameSaveStore.cs` 同步版本、导入与一致性检查。
- 在现有 Core 模块内集中法宝查询、调配与流转规则，可增加聚焦的 `PersonalRelics.cs` partial 文件，不引入服务层、背包系统或泛化装备接口。
- 将器阶、最低境界、形制风格和固定效果收敛到少量模板；模板生成、导入校验、自动补位、实际效果与界面说明读取同一事实，不各写一份数值。
- 通过现有 `GameCommand` 增加 `personal_relic` 命令：`Target` 为本宗在世人物的正整数 ID。`Option` 为物品正整数 ID 时执行赐予，目标必须为在山重点人物，只校验目标御使资格及来源归属、在场状态，目标旧物回库，不执行双向强制交换；交付成功设 `KeepAssigned`。`Option` 为明确的 `auto` 时仅恢复托管，允许旧受赐者已非重点或仍在外，但不能当场给在外人物换装。不接受空值卸下。选择已持物只设为保留，不伪造转移；重复保留或恢复托管无新变化时不追加事件。
- 底层更新归属集中复用，死亡场景的判断仍由对应业务流程负责，不建立通用事件总线。

### 阶段二：获取、效果和生命周期

- 在 `Stewardship.cs` 接入归山获取、重获与历练死亡流转；活动被取消或主角提前寿尽时不发放成功归山奖励。
- 在 `CultivatorCombat.cs`、`Conflicts.cs` 接入个人伤害、战报快照、战后缴获与战场重获、散修与流亡处理。
- 在 `WorldEvolution.cs` 接入在山寿尽回库、在外寿尽遗失、散修被动寿元与安全节点自动补位；核对所有实际执行的死亡写入路径，不给散修增加主动玩法。
- 将真实持有与本人效果放在统一入口，供 `CultivatorDamage` 的实际交锋和 `CanChallengeGarrison` 的出征预估共用；保留跨境群攻与同境单目标规则，不新增每月装备任务。在真实移动与脱宗前维护可靠地域，不用任意地域兜底掩盖归属漏洞。
- 为 `Power` 和镇宗实际倍率明确过滤范围，保留原有最强三件规则。
- 不顺手重构无关战斗、成长、外交与后台调度代码。

### 阶段三：界面与只读观察

### 原生与玩法验收

1. 使用隔离世界验证查看、赐予后旧物回库、交给执事、在外禁用、死亡后的去向展示与存档恢复，不接触玩家存档。
2. 构造确定性夹具覆盖第4.5节的五类故事链，包括同一 ID 的缴获后夺回、高阶遗宝暂存待传、护道双亡后原地重获，不能用替换物品或捏造人物关系冒充结果。
3. 从自然开局观察获取频率和自动分配，确认不需要逐人管理、不清库也能继续有益发现，普通变化不弹窗或暂停；夹具不冒充自然流程。
4. 对照三个器阶的同境战斗、实际持有前后与有无护道的历练，检查效果有感但不是免死或跨境必胜；高阶传承可越过“已持同类低阶物”的自动换新门槛，不造成强制刷宝或全员换装。
5. 零法宝操作验收：不点击任何法宝入口，用确定性夹具走完“自动得宝—实际使用—托管同类升阶—死亡回收—下一人继承”，无等待祭炼、清库或领战利品提示；人物对照有保留标记时不被强换，恢复托管后正常换新。另确认无个人法宝的合法世界仍可推进培养、战役与终局。
6. 独立验证支线：人物持宝转散修 → 正常月结寿尽 → 原地域遗失 → 另一位真实人物通过历练或占领战场重获。可用接近寿元的隔离夹具缩短时间，但不能直接改写持有人跳过中间规则。
7. 美术按30张独立图标验收：六组各五张且与模板一一对应，透明度正确，小尺寸下组内器形仍有区分，不用换色凑数，列表不挤占人物信息；同组数值一致，同一物品流转后图片不变，器阶与效果不依赖颜色猜测；占位或缺图时名称、规则、读档和过月仍可用。

## 10. 完成定义

- 镇宗效果无退化，个人效果不重复算到全宗；所有获取、持有、死亡与宗门变动路径完成且可保存恢复。
- 人物区分度与历史因果可见，重点人物有少量明确干预入口，普通门人无需配装。
- 世界观与规则一致：器物有可追溯来历，御使有境界与认主约束，人物生死和宗门变动不凭空增删或瞬移法宝；十宗风格不变成十套互斥装备系统。
- 第4.6节每条转换都有明确的规则入口、事务时序和测试；散修支线不是永久冻结的持宝出口。这里只证明轻量法宝及其必要生死流转的设计闭环，不等于修仙世界所有系统已经完整。
- 存档兼容、规则测试和原生界面验证通过，相关设计与指南反映实际实现。
- 第2.1节休闲约束通过验收，日常法宝管理必需点击数为零；可选赐予有可见结果且可恢复托管，不以自动化覆盖玩家选择。不将本方案替代整局自然胜利与重建流程验收。
