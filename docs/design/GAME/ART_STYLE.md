# 美术与 HUD 风格规范

## 适用范围与事实边界

本文件是《无限修仙 · 宗门纪》的人物美术、宗门识别与原生界面的统一生产和验收规范。规范的存在不代表资源已经制作完成或功能已经接入；当前实现仍以 [PROJECT_DESIGN.md](../PROJECT_DESIGN.md) 和 [Game 模块](MODULE.md) 为准。效果图是视觉参考，不是运行截图，也不提供额外玩法事实。

## 1. 固定视觉基准

- 可分发的人物基准为 [00号人物](../../../src/InfiniteDao.Game/Assets/cultivator-00.png)与[01号人物](../../../src/InfiniteDao.Game/Assets/cultivator-01.png)：固定脸部比例、线条、发束、清晰明暗和服装完成度，不改成厚涂。
- 本机已确认的画法与完成度参考为 `artifacts/design-previews/20261111-official-reference-calibration/qingyun-style-test.png` 和同目录的 `qingyun-finished-splash.png`。
- 本机整屏 HUD 构图参考为 `artifacts/design-previews/20261111-full-hud/main-hud.png`：浅色面板、玉青导航、青绿山河和原生游戏控件。实际配色以本文月白、浅灰青及哑金规则为准；无本机效果稿的工作区以本文颜色、排版及控件规格为准。

这些参考位于本地 `artifacts/`，不作为源码提交，也不作为运行时资源依赖；投入游戏的图片必须保存在 `src/InfiniteDao.Game/Assets/`。外部作品只用于观察画法，不复制其角色、服装、图标、游戏标识或其他识别元素，不将外部参考打包为项目美术。

**风格定义：精致二次元国风，清晰赛璐璐明暗，玉青与月白的宗门经营界面。** 不是写实人物绣像、泛国风手游厚涂，也不是把探索动作游戏的 HUD 原样搬进策略游戏。

## 2. 人物画法

### 脸、头发与上色

- 成人约七头身；男女、青年、中年和长者都保留可辨识的动漫五官，不画幼儿 Q 版比例。
- 脸用清晰眼型、小鼻和简洁嘴形建立性格。皮肤以亮面和一组阴影为主，不塑造写实鼻梁、颧骨或皮肤纹理。
- 头发先设计大块发束，再补少量结构线；不画密集碎丝、油亮银白高光或无意义的大量飘发。
- 使用细而明确的轮廓线。衣服是主色与成组阴影，少量柔和过渡只辅助体积；不以连续喷枪渐变代替形状设计。
- 布、皮革、金属和玉石靠色块与少量高光区分。皮肤、布面不得全部泛金属光。

### 服装、武器与动作

- 先设计肩线、腰线、衣摆、袖形和负空间，再添加饰品。长袍必须留出可读的手、腿和武器轮廓。
- 细节集中在领口、肩部、腰部、武器和一处衣角；胸腹、裤腿等区域留有完整安静色块。
- 每个人只突出一至两个主题，例如云剑、草木、炉火、星纹。禁止满身统一金色花纹、饰链和无功能绑带。
- 每个角色具有独立脸型、眼型、发型和轮廓；仅换衣服颜色不算新的立绘。
- 动作克制而有性格，手部和武器结构清楚。资源池立绘不附带大面积遮挡人体的法术效果。
- 衣着完整，不靠暴露或不合理盔甲表达角色差异。长者以发色、少量年龄线和神态区分，不切换为写实画风。

## 3. 五十张人物资源规格

| 项目 | 规范 |
|---|---|
| 数量与稳定编号 | 50 个不同人物，ID `0–49`，编号不因宗门或职位变化而改变 |
| 正式文件 | `Assets/cultivator-00.png` 至 `Assets/cultivator-49.png` |
| 单张交付尺寸 | 512 × 768，保持比例，不拉伸人物 |

允许并发生成双人生产图：画面严格左右等分，每半幅一名完整人物，身体、武器和衣摆不得跨越中线；无文字、分隔线或场景。机械分割后分别保存正式单图。双人生产图不是游戏中的人物 ID，也不构成两个角色共用一张头像。

### 人物绑定验收要求

- 创建人物时从资源池选一次并保存到人物数据，不在绘制、读档、升境或继任时重新随机。
- 优先减少在世人物的重复；50 张是可复用资源池，不是世界人口上限，也不保证超过 50 人后仍然人人唯一。
- 继任掌门使用继任者自己的立绘；已故掌门的立绘和生平保留在该人物记录中。
- 宗门始终以宗徽代表身份，人物立绘不能代替宗门标识，也不能让全宗共用掌门的脸。

### 个人法宝图标

- 个人法宝使用 30 张独立的 512 × 512 透明 PNG，六组各五种独立造型；每张只表现完整单件器物，保留安全留白，不用拼图或简单换色代替新造型。
- 轮廓、材质和明暗与国风赛璐璐界面一致，缩小后仍可辨认。真实透明背景不含棋盘格、底板、文字或人物。
- 正式资源位于 `Assets/relic-{TemplateId}.png`，由固定模板 ID 对应本地图片；存档不记录图片路径。同组造型只改变外观，不改变规则效果。

新建标准世界和紧凑测试世界均包含下列十宗；旧六宗存档迁移时保留原有宗门和地图，不强行加入新宗。具体开局及规则以 Core 实现及其同步设计为准。

## 5. HUD 色彩与排版

| Token | 色值 | 用途 |
|---|---|---|
| 玉青 | `#173D3C` | 导航底、主按钮、强结构 |
| 月白 | `#F7FAF8` | 面板底、冷白留白 |
| 墨青 | `#263D42` | 正文、关键数字 |
| 哑金 | `#AAA58F` | 日期刻度、徽记与极少量点缀，不作大面积描边 |
| 朱砂 | `#A84F43` | 战事、死亡、危险与待决提醒 |
| 雾青 | `#88B4AB` | 选中浅底、地图气氛与辅助装饰 |

- 标题使用本机楷体类字体，正文采用清晰中文 UI 字体，不打包 Windows 字体文件。
- 页面标题 26–32，数值 22–26，正文 15–17，辅助说明不低于 12；小字不承担主要操作含义。
- 以 1440 × 900 设计，并在 1100 × 700 的最小窗口核对换行、滚动、点击和溢出。
- 平时不用黑色大面板；玉青承担导航和主操作，月白面板与浅灰青边线保持同一冷色系。哑金仅点缀，不叠多层黄边或铺黄底；宗门识别色不跟随 HUD 配色改动。

## 6. 整屏布局与交互

- **顶部资源带**：宗徽、宗门名、灵石、灵材、门人、疆域、战力、安定及存档/设置。压薄高度，不堆巨型统计卡。
- **左侧导航**：山河舆图、山门内政、门徒名册、诸宗外交、道统宝库、青岚史书；同时保留待决议事和终局入口。
- **中央内容**：地图内使用浮动题签和底部图例/缩放操作，避免外置标题、图例挤占地理视野。题签采用简洁切角、实色底和独立文字内边距，装饰不进入主副标题区域；名册突出头肩像与身份，人物详情使用完整立绘。
- **右侧地域栏**：正常山门状态首屏展示归属、地貌、人口、灵脉、发展、护山阵、产出和现任掌门；完整产出说明与相邻地域放入可操作的地域档案。战役与补给、人物小传均有实际入口，特殊战况或流亡信息可滚动查看。
- **底部时间带**：日期牌为单层浅青切角框，不叠弧顶、双框或角落回纹；十二刻度盘与日期/状态文字组垂直居中，左右留16、上下留12逻辑像素。保留年月、暂停状态、三档速度、继续/暂停及推演一载。最近两条本宗纪事可点开公共事件，长标题收省并保留提示；待决议事、流亡和终局约束不得隐藏。
- 通用操作使用月白切角细框，与玉青主操作和导航形成层级；导航使用单层浅青边线，不拉伸主按钮的多重饰框。顶部、军情、缩放与时间按钮不随横向行拉高。时间控件统一垂直居中，日期牌保持紧凑；纪事与保存状态归为浅青底信息组，不留下孤立的底部状态行；左栏底部宗策摘要与外框保留16逻辑像素留白。
- 护阵、资源、名称、宗徽、领土、选中态、连接和战线由世界数据绘制，不烘焙进地图背景。
- 不增加手操战斗条、抽卡、商城、体力、联网组队或无对应规则的升级按钮。概念图中的样例数字不作为规则常量。
- 所有数据与操作均由原生控件和世界状态构成；不得把整张效果图铺在屏幕上冒充交互 UI。
- 选中、悬停、按下、禁用和键盘焦点必须可区分；滚动、下拉框、失焦暂停和实时刷新遵守 Game 模块的生命周期约束。

## 7. 并发生产与验收

1. 所有批次使用相同画法基准、统一正负面约束及固定编号，不允许并发任务自行更换风格或编号。
2. 角色批次彼此独立可并发；失败只处理对应批次，不盲目重发已经成功或结果尚不确定的任务。
3. 逐批检查是否恰好两个人、是否有越界/缺肢/重脸、脸与衣料是否仍为赛璐璐、透明度是否真实、编号与描述是否对应。
4. 分割后检查尺寸、全身完整性、头肩裁切和缩小后的辨识度；必须形成 50 个独立有效 PNG，而不是重复复制或单纯换色凑数。
5. 地图检查无固定文字、归属、领土边界和节点；HUD 检查对比度、真实数据绑定、十宗适配及更换掌门后的身份对应。
6. 交付区分效果稿、美术资源、已接入界面和已验证行为，不把生成成功当成游戏集成或原生窗口验收通过。
