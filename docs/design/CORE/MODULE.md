# Core 模块

## 职责与边界

本模块位于 `src/InfiniteDao.Core/Game/`，维护权威世界和全部游戏规则，只依赖 .NET 基础库。全局结构见 [PROJECT_DESIGN.md](../PROJECT_DESIGN.md)。Core 不调用模型、不操作 Godot 节点、不读写存档文件。

## 代码入口

- `WorldFactory.cs`、`VastWorld.cs`：十宗模板、50张人物立绘的固定编号分配、种子世界与默认192地域地图；紧凑测试地图为20地域。
- `GameState.cs`：世界、宗门、地域、人物、事件、战役、历练、战报和历史数据。
- `PersonalRelics.cs`：个人法宝固定模板、数据一致性校验、流转、自动分配与赐予。
- `GameEngine.cs`：命令、合法性校验、历史写入及公共规则查询。
- `WorldEvolution.cs`：月度结算、策略采用、人物成长和掌门继承。
- `Cultivation.cs`：个人特性上限、日常供养、突破费用与优先预算、飞升/留世与底蕴。
- `Stewardship.cs`、`Provisions.cs`：自动经营、供养、采办与军需预留。
- `Campaigns.cs`、`Conflicts.cs`、`CultivatorCombat.cs`：出征、目标竞争、补给与逐人交锋。
- `CouncilEvents.cs`：关键议事、选项成本和实际效果。
- `AgentPlans.cs`、`SectAgentMemory.cs`：模型计划的业务校验和可保存的公开记忆结构。

## 数据模型

`GameState` 保存月份、随机状态、提交版本和实体集合，通过 `Copy()` 复制世界后执行修改。实体关系使用宗门/地域字符串 ID、人物/事件整数 ID；历史 `Causes`、战役与历练起因、法宝来源必须引用有效事件。

- `Sect` 的战略、资源、领地与生存状态是规则事实，不从叙事文本推导。
- `Cultivator` 以 `Alive`、`Injury`、`AgeMonths`、`RealmMonths` 等字段记录持续成长和生死；`Focused` 与 `GuardianId` 影响培养和历练。`Portrait` 为0—49固定人物资源编号，新人物优先选择全世界在世门人使用最少的编号，继任不重抽。
- `Campaign`、`Expedition` 持续占用参与人物，不能双重部署；`BattleReport` 记录实际交锋。
- `GameEvent.Choices` 决定可选身份和成本；场景与选项由规则定义，选择效果由命令分支执行。既有存档的 `NarrativeSource` 和 `Flavor` 保留为展示数据，不生成规则效果，也不触发模型请求。
- `SectAgentMemory.Plan` 是意图，不等于已执行行动；执行后的 `AgentDecision` 和 `Chronicle` 才记录采用与结果。
- 个人法宝通过 `Relic` 的固定模板、持有人和地域记录状态，`Chronicle.RelicChange` 记录结构化流转引用；个人法宝不进入镇宗法宝战力前三件。交锋战报保存当时的实例名称及模板类别、器阶和效果，不使用模板名称代替物品名称；有效物品名称为空或空白时，快照显示“无名法宝”，无物品则不显示法宝。
- 三个器阶分别以炼气、筑基、金丹为最低御使境界；御敌增加本人伤害8%／12%／16%，护身将本人历练危险相对降低15%／20%／25%。各规则组五种固定造型效果相同。安全节点优先复用库存，按器阶递减分配，只填空位或为未保留的同类旧物严格换新；旧物可继续传给下一人。
- 归山按地域先重获遗失物，再分配库存；仍有需求时首次发现保底、后续按10%判定。寿尽、历练和战场按实际地点与战场归属回收或遗失；转散修者保留随身物并被动衰老。流转记录保留当时前后归属与事件因果，认主不设等待。

## 关键流程

1. `GameEngine.Command` 校验并执行战略切换、议事、重点培养、护道人和重建等命令。
2. `AdvanceMonth` 拒绝跳过待决议事、流亡重建或局终，采用完整的存续敌宗决策集合。
   大乘108月起尚未提醒者先按境龄倒序、重点和ID排队生成飞升议事，不推进月与费用；裁定全部已到提醒期的人物后才月结。
3. 月结处理生产、供养、修炼、寿元、飞升/留世、历练、经营和战争，并生成需要玩家裁定的事件。
4. 世界校验通过后，由 Application 提交存档；Core 自身不提交 UI 或磁盘状态。

## 当前规则约束

- 地域有唯一控制者和相邻关系，只能向接壤地域出征；竞争目标不能由多个宗门重复占取。
- 五个战略方向为 `balanced`、`prosperity`、`cultivation`、`expansion`、`diplomacy`；重点培养至多三人。
- 八境为炼气、筑基、金丹、元婴、化神、分神、合体、大乘；寿元28/36/48/62/78/94/110/130年，最低境龄6/12/24/36/48/60/72月。五档先天特性固定影响修炼、实战伤害和可达境界，重点培养不会改写特性。新档仅支持Schema4，不迁移旧档。
- 普通供养与修为培养分开付费，顶境/满修为也支付高阶日常供养；全宗缺供时不烧培养材料。成熟候选按重点、特性、境界优先备资，采办、营建、他人日常培养和较低优先级晋阶不能抢预算；优先者达到110修为后不为补满120而挪用自己的突破费，尚未成熟则仍可正常修炼。军阵/道藏高等级花费指数增长，招新受常例收入余裕约束。
- 大乘满120月默认飞升；满108月起为未裁定的本宗大乘发一次飞升之议。选择留世或在详情开启意愿不立即收费，到期后逐月付巨额灵石与灵材，必须保住常例和正在进行的战役军需；不足则飞升。寿尽优先且不收当月留世费，飞升不视为死亡，物品归宗、掌门继任。底蕴每次加1，生产/修炼每点+5%，最多50%。
- 常规议事资源费/收益随本宗产出缩放，规模写入事件；跳过明显无收益的饱和场景，并移除已封顶的道藏/军阵付费提升。天才拜山至少天灵根；资质提升优先尚未满值且重点/特性更高的人物。
- 历练与战争有真实时长、资源开销和死亡风险；更高境护道人实际同行，不保证免死。
- 战役按月消耗军需，断供撤军。无主地基础2+护阵月、有主地6+2×护阵月，险地加2、距离每6格加1；攻方月度战疲+1，守阵每级增伤8%，燃灵护山费用随本宗供养增长。境界、军阵、法宝、战术、情报、伤势、战疲和补给共同参与逐人战斗。
- 同轮双方伤害同步结算；低一大境界的伤害倍率为0.12，多境差递乘，不能用总战力相等替代个体对局。
- 每轮按境界与人物 ID 排列敌人并轮转首目标；首目标境界较低时，高境修士最多攻击四个不同低境目标，不会重复攻击同一目标或额外攻击同境、高境目标。首目标同境或更高境时仍只攻击一次；群攻不取消低境方同轮反击。
- 真实出征与自动评估共用七成可调动门人的选择，排除在外及伤势达到60的门人，至少两名可调动者才能组军。守军构成也共用：有主地域取在场门人，无主地取3加护阵等级名地方守卫，首名筑基、其余炼气，不能因没有宗门所有者跳过评估。评估使用双方承伤与攻击压力的几何平均，按对手最高境界保守估算伤害及群攻，并计入实际军阵、法宝、情报、战疲、守阵与难度倍率；预估不足守方80%时暂缓，不消耗规则随机数，不改写展示总战力或直接决定胜负。
- 无额外强化、正常供给与低级护阵下，一个元婴能击败十名参战金丹；同境或向更高境攻击不获得群攻。伤势、强阵、补给不足与战疲仍可能逆转跨境优势，48轮僵持不算攻方占领。
- 十宗新世界每宗有独立山门与完整双向外交。雷霆阁攻击加成10%；金禅寺在山门的月度伤势恢复为5；星罗宫初始道藏增加1、月度修为增加1；幽篁楼初始情报为3。原六宗天赋保留。
- 玩家失守最后山门后保留幸存门徒与道统，仍可在同一世界重建；消灭其余所有宗门后进入统一终局，按世界实际宗门集合判断而非固定数量。
- 世界仅支持 SchemaVersion 4 的十宗新档；Core 与 Infrastructure 均拒绝其他版本，不迁移或改写旧文件。
- 具体平衡常量由对应规则文件定义；修改常量须同时核对本模块、核心设计和回归断言，不把未验证数值写成已确认结论。

## 变更与验证

数据关系变更同步更新核心设计的“数据模型”；命令或月结变更同步更新“关键流程”。至少运行 `tests/InfiniteDao.Core.Tests/`，涉及会话或持久化时加跑 Integration。核心回归覆盖确定性、长期演化、资源、历练、生死、供给、战役、流亡与统一。

执行方法见 [开发变更流程](../../DEVELOPMENT.md)，验收边界见 [VERIFICATION.md](../../VERIFICATION.md)。
