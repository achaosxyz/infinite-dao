# Application 模块

## 职责与边界

本模块位于 `src/InfiniteDao.Application/`，通过 `GameSession` 连接 Core、Agents 和 Infrastructure。全局结构见 [PROJECT_DESIGN.md](../PROJECT_DESIGN.md)。它负责会话与任务生命周期，不实现另一套经济、成长或战斗算法。

## 代码入口

- `GameSession.cs`：配置读取、提交版本、新局、命令、月结和成功保存后的世界替换。
- `GameSession.Background.cs`：按需启动独立后台任务、并发上限、取消、重试与计数事件。
- `GameSession.Background.Results.cs`：串行收集结果、校验目标、保存公开记忆和离线转换。

## 数据与并发契约

- `State` 是当前已提交世界，前台操作在副本上执行，保存成功后替换引用。
- `Gate` 由调用方用于串行化 `Advance`、`Execute`、`Commit` 与 `PumpAgents`；方法内部不再次获取同一锁。
- 后台模型等待不持有 `Gate`，任务只使用独立快照，通过线程安全队列返回结果，不直接修改 `State`。
- 任务代际、取消源、活动任务和结果队列是运行态，不进入 JSON 存档。
- 同一宗门只运行一个规划任务；各宗策略任务遵守配置中的并发上限，不创建议事描述任务。
- 每个世界保存生成请求、上下文计数请求和已报告 token；密钥和供应商响应正文不进入状态。

## 关键流程

1. `NewGame` 创建并保存世界，作废旧任务，再按当前情况启动需要的后台任务。
2. `Advance` 检查提交版本，收集已完成结果，以合法计划或现有战略完成一个规则月份，保存后继续调度。
3. `Execute` 收集结果后执行玩家命令；显式模式切换取消旧任务，恢复智能世界会要求重新观察。
4. `PumpAgents` 非阻塞收集完成队列；仅更新后台元数据和公开记忆时不增加回合 `Revision`。
5. `Commit` 用于外部加载/导入：验证和保存成功后替换世界，再取消并作废旧代际任务；失败不替换当前世界。

## 计划采用

- 等待模型期间继续执行宗门当前合法方向和目标，以 `standing` 来源记录；不会因等待而冻结月份。
- 新计划返回时用当前世界校验；不再可达的目标不执行，公开提交仍保留并触发重新观察。
- 接受计划只更新该宗记忆，下一次月结才执行；复盘期限从采纳月份计算，观察月份保留。
- 议事标题、正文和选项使用 Core 定义；后台策略结果不修改待决议事，也不因待决议事触发额外模型请求。
- 新局或加载产生新任务代际，即使旧 HTTP 请求迟到返回，也不能回写新世界。

## 失败处理

单个失败任务初次调用后按1/2/4秒退避重试3次，成功任务不重复执行。仍失败则把模式设为 `rules`，更新可见 `AgentStatus`、写入 `agent` 历史并取消其他未完成任务；时间继续流逝。配置本地校验失败会明确离线，不伪装成已发送请求。恢复 `llm` 需要玩家手动操作，不循环自动联网。

这不是全局调用额度：单个 Agent 工具回合内的查询、上下文计数与 compact 各按实际请求统计。网络超时和重试仍可能计费。

## 变更与验证

修改提交时机、任务代际、模式切换或后台结果应用时，运行 `tests/InfiniteDao.IntegrationTests/`，覆盖慢响应下推进、重试恢复/耗尽、并发上限、重载隔离、失效目标，以及待决议事不改写、不调用模型。UI 轮询或窗口生命周期同时变化时增加原生验证，步骤见 [验证验收流程](../../VERIFICATION.md)。
